# Migration guide 16.0.0 -> 17.0.0

## Breaking Changes

### Themes

The SASS based themes (saga, arya, vela, nova, luna, bootstrap4, material, the old aura, ...) and the
`primefaces-themes` jar were removed. PrimeFaces 17 comes with design token based themes in the `primefaces` jar:
`aura` (default), `lara`, `nora`, `metal` and `glass`, each with light and dark mode, see [Theming](../17_0_0/core/theming.md).

* Remove the `primefaces-themes` dependency and set `primefaces.THEME` to one of the new themes (or leave it out for
  `aura`). Old names (`saga`, `nova-light`, `aura-light-emerald`, ...) point to a stylesheet that does not exist; in the
  `Development` project stage a warning is logged.
* Dark mode is the CSS `color-scheme` of the page instead of a separate theme (`arya`, `vela`, `*-dark`).
* The default `color-scheme` is `light dark`, i.e. it follows the operating system: users with a dark OS setting get dark
  components after the upgrade. Applications whose own CSS is light only set `:root { color-scheme: light; }`.
* The CSS variables of the SASS themes (`--primary-color`, `--surface-a`, `--surface-500`, `--text-color`,
  `--font-family`, `--border-radius`, `--focus-ring`, `--maskbg`, `--blue-500`, ...) are gone: use the `--p-*` tokens or
  map the old names, see [Migration from the SASS themes](../17_0_0/core/theming.md#migration-from-the-sass-themes).
* Higher browser requirements: Chrome / Edge 123+, Firefox 128+, Safari 18+ (`light-dark()`, `color-mix()`, relative
  colors, CSS nesting).
* The CSS of the components was rewritten for the tokens: application CSS that overrides PrimeFaces styles by selector
  may need adjustments, customize with tokens instead. All PrimeFaces CSS lives in cascade layers, so unlayered
  application CSS wins without `!important`.
* Custom SASS themes (`primefaces-<name>/theme.css` from the theme designer) do not work anymore; a custom theme is a CSS
  file with the tokens of a theme.
* `PrimeFaces.env.getThemeContrast()` reads the `color-scheme` of the page instead of the theme name.
* The components do not render the jQuery UI `ui-shadow` class anymore (overlays, dialogs, menus, tooltips, growl,
  sticky, ...): the shadow is part of the component styles and set by its token (e.g. `--p-dialog-shadow`,
  `--p-menu-shadow`). Application CSS that selects `.ui-shadow` to style or hide the shadow of a component must use the
  component class (e.g. `.p-dialog-box`) or the token instead.
* The components do not render the jQuery UI `ui-helper-clearfix` class anymore (the layouts are flex / grid, the few
  floats are contained by the component CSS).
* The jQuery UI helper classes for own markup are gone: `ui-helper-hidden` and `ui-helper-hidden-accessible` (use
  `p-hidden` / `p-hidden-accessible`), `ui-helper-reset`, `ui-shadow` and `ui-corner-*` (use own CSS or the tokens, e.g.
  `border-radius: var(--p-content-border-radius)`).

### Style classes

The style classes of the components were renamed from the jQuery UI prefix `ui-` to `p-`, e.g. `ui-widget` ->
`p-widget`, `ui-state-active` -> `p-state-active`, `ui-datatable` -> `p-datatable`, `ui-inputfield` -> `p-inputfield`,
`ui-c` -> `p-c`. Exceptions and renames that are not 1:1:

* The Grid CSS keeps its names (`ui-g`, `ui-g-*`, `ui-sm-*`, `ui-md-*`, `ui-lg-*`, `ui-xl-*`, `ui-grid*`).
* The popup of `p:keyboard` is rendered by the jQuery keypad plugin, its classes keep their jQuery UI names
  (`ui-widget`, `ui-widget-content`, `ui-widget-header`, `ui-corner-all`, `ui-state-*`).
* The panel of `p:datePicker` is `p-datepicker-panel` (formerly `ui-datepicker`), `p-datepicker` is its container.
* `p:inplace` with a password editor carries `p-inplace-password` instead of `p-password`.
* Icons the application sets (`icon="pi pi-check"` of buttons, menu items, tree nodes, ...) do not get the jQuery UI
  class `ui-icon` anymore, only their slot class (`p-button-icon-left`, `p-menuitem-icon`, `p-treenode-icon`, ...);
  `p-icon` is the class of the icons the components draw themselves (see [Icons](#icons)). jQuery UI icon classes as
  `icon` value (e.g. `icon="ui-icon-check"`) are not styled anymore, use an icon library such as PrimeIcons
  (`icon="pi pi-check"`).

Application CSS, JavaScript and tests that select PrimeFaces markup by `ui-*` classes (e.g. `.ui-datatable .ui-state-highlight`,
`$('.ui-dialog')`, `By.className("ui-inputfield")`) must use the `p-*` names; own markup that borrows the look of the
components (e.g. `styleClass="ui-widget-content"`, `ui-fluid`, `ui-inputtext-sm`) uses `p-widget-content`, `p-fluid`,
`p-inputtext-sm`. Public style class constants of the components and of `HTML` have the new values.
Some of these classes are also hooks the widgets look for, with the old name they silently do nothing: the buttons
of a global `p:confirmDialog` / `p:confirmPopup` (`p-confirmdialog-yes` / `-no`, `p-confirm-popup-yes` / `-no`), the
close element of `p:notificationBar` (`p-notificationbar-close`) and the float label wrapper (`p-float-label`).

### Icons

The icons the components draw themselves (toggler, close, sort, dropdown, filter, pagination, checkbox, ...) are
rendered with semantic classes instead of the jQuery UI icon classes (`ui-icon ui-icon-triangle-1-e`,
`ui-icon-closethick`, ...), named after the component and the icon (see [Theming](../17_0_0/core/theming.md#icons)):

```html
<!-- before -->
<span class="ui-icon ui-icon-closethick"></span>
<!-- now -->
<span class="p-icon p-close-icon p-panel-close-icon"></span>
```

* The component class carries the PrimeFaces component name also where the icon token is named after PrimeUIX:
  `p:growl` `p-growl-close-icon` / `p-growl-<severity>-icon` (tokens `--p-toast-*`), `p:selectOneMenu`
  `p-selectonemenu-dropdown-icon` / `-filter-icon` (`--p-select-*`), `p:selectCheckboxMenu`
  `p-selectcheckboxmenu-*-icon` (`--p-multiselect-*`), `p:spinner` `p-spinner-increment-icon` / `-decrement-icon`
  (`--p-inputnumber-*`), `p:chips` `p-chips-chip-remove-icon` (`--p-inputchips-chip-remove-icon`),
  `p:selectOneListbox` / `p:selectManyMenu` `p-selectlistbox-filter-icon` (`--p-listbox-filter-icon`), `p:messages`
  `p-messages-<severity>-icon` / `p-messages-close-icon` (`--p-message-*`), `p:dataScroller`
  `p-datascroller-loading-icon` (`--p-dataview-loading-icon`).
* Icons that change with the state (expanded / collapsed, minimized / maximized, ...) keep one class; the widgets
  switch the state of the component (e.g. `aria-expanded` on the toggler) instead of the icon class. The sort icon of
  `p:dataTable` / `p:treeTable` is `p-icon p-sort-icon p-datatable-sort-icon` plus `p-datatable-sort-asc-icon` /
  `p-datatable-sort-desc-icon` (treeTable: `p-treetable-*`) instead of `ui-icon-carat-2-n-s` / `ui-icon-triangle-1-n` /
  `ui-icon-triangle-1-s`.
* Checkbox icons: `p-chkbox-icon p-icon p-checkbox-icon` plus `p-checkbox-checked-icon`,
  `p-checkbox-indeterminate-icon` (partially checked) or `p-checkbox-crossed-icon` (`p:triStateCheckbox`) instead of
  `ui-icon ui-icon-check` / `ui-icon-minus` / `ui-icon-closethick` / `ui-icon-blank`.
* Radio buttons: the `p-radiobutton-icon` has no icon classes anymore (`ui-icon ui-icon-bullet` / `ui-icon-blank`), the
  checked state is `p-state-active` on the `.p-radiobutton-box`.
* Application CSS / JavaScript / tests that select the old icon classes on PrimeFaces markup must use the new classes
  or the state; for icons the application sets see [Style classes](#style-classes).
* JSF attributes for icons the components draw themselves were removed without replacement, configure the icons with the
  icon tokens or classes in CSS:
  * `p:panel`: `closeIcon`, `collapsedIcon`, `expandedIcon`, `menuIcon` (`--p-panel-close-icon`,
    `--p-panel-toggle-collapsed-icon`, `--p-panel-toggle-expanded-icon`, `--p-panel-menu-icon`)
  * `p:breadCrumb`: `homeIcon` (`--p-breadcrumb-home-icon`)
  * `p:chip`: `removeIcon` (`--p-chip-remove-icon`)
  * `p:dataView`: `gridIcon`, `listIcon` (`--p-dataview-grid-layout-icon`, `--p-dataview-list-layout-icon`)
  * `p:datePicker`: `triggerButtonIcon` (`--p-datepicker-dropdown-icon`)
  * `p:fileUpload`: `chooseIcon`, `uploadIcon`, `cancelIcon` (`--p-fileupload-choose-icon`, `--p-fileupload-upload-icon`,
    `--p-fileupload-cancel-icon`); the drag overlay icon is `--p-fileupload-drag-overlay-icon` (was `pi pi-upload`)
  * `p:galleria`: `closeIcon` (`--p-galleria-close-icon`)
  * `p:rowToggler`: `expandIcon`, `collapseIcon` (`--p-datatable-row-toggle-collapsed-icon`,
    `--p-datatable-row-toggle-expanded-icon`); the `data-expand-icon` / `data-collapse-icon` attributes are gone
  * `p:scrollTop`: `icon` (`--p-scrolltop-icon`)
  * `p:spinner`: `upIcon`, `downIcon` (`--p-inputnumber-increment-icon`, `--p-inputnumber-decrement-icon` for the default
    stacked layout; the `horizontal`, `horizontal-after` and `vertical` layouts draw `--p-icon-plus` / `--p-icon-minus`)
  * `p:triStateCheckbox`: `stateOneIcon`, `stateTwoIcon`, `stateThreeIcon` (`--p-checkbox-checked-icon`,
    `--p-checkbox-crossed-icon`); the `data-iconstates` attribute is gone
* Widget options of these attributes were removed as well (`PrimeFaces.widget.Panel` `collapsedIcon` / `expandedIcon`,
  `PrimeFaces.widget.Galleria` `closeIcon`, `PrimeFaces.widget.DatePicker` `icon`, ...). `PrimeFaces.widget.Log#add`
  takes the icon classes as its `icon` argument.
* Public constants with icon classes in the component classes changed their values or were removed (e.g.
  `Panel.DEFAULT_CLOSE_ICON`, `TriStateCheckbox.UI_ICON`, `Spinner.ICON_BASE_CLASS`,
  `AbstractMenu.SUBMENU_RIGHT_ICON_CLASS`, `PanelMenu.ACTIVE_TAB_HEADER_ICON_CLASS`,
  `HTML.RADIOBUTTON_CHECKED_ICON_CLASS` / `RADIOBUTTON_UNCHECKED_ICON_CLASS` -> `HTML.RADIOBUTTON_ICON_CLASS`).
  Custom renderers that extend PrimeFaces renderers and override the icon methods need to be adapted: e.g.
  `AccordionPanelRenderer.encodeTab(...)` lost its `rtl` parameter, `PanelRenderer.encodeIcon(...)` got an `expanded`
  parameter, `RowEditorRenderer.encodeIcon(...)` and `RatingRenderer.encodeIcon(...)` got an icon class parameter,
  `CascadeSelectRenderer.encodePanel(...)` / `encodeList(...)` / `encodeListItems(...)` got a `valueToRender` parameter,
  `AccordionPanelRenderer.encodeIcon(...)` does not add `ui-icon` anymore, and `InplaceRenderer.encodeButton`,
  `DataViewRenderer.encodeButton`, `FileUploadRenderer.encodeButton` and `WizardRenderer.encodeNavigator` take the full
  icon class (they do not add `p-button-icon-left` / `-right` themselves anymore).
* Loading spinners of the components are icons of the theme instead of the PrimeIcons classes `pi pi-spin pi-spinner`:
  ajax buttons, `p:autoComplete` and `p:selectOneMenu` render `p-icon-loading p-icon p-loading-icon p-ajaxstatus-loading-icon`,
  `p:outputPanel deferred` `p-outputpanel-loading p-icon p-loading-icon p-outputpanel-loading-icon`, the default loader of
  `p:dataScroller` `p-datascroller-loading-default p-icon p-loading-icon p-datascroller-loading-icon`.
* `p:carousel`: the navigation icons are theme icons (`--p-carousel-prev-icon`, `--p-carousel-next-icon`, vertical
  `--p-carousel-prev-vertical-icon` / `-next-vertical-icon`) instead of `pi pi-chevron-*`.
* `p:cascadeSelect`: the dropdown and group icons are theme icons (`--p-cascadeselect-dropdown-icon`,
  `--p-cascadeselect-group-icon`) instead of `pi pi-chevron-down` / `pi pi-angle-right`. The label is always rendered as
  `p-cascadeselect-label` (with `p-cascadeselect-label-placeholder` while it shows the placeholder), the
  `ui-cascadeselect-label-empty` class and `CascadeSelect.LABEL_EMPTY_CLASS` are gone; the selected item carries
  `p-state-active`.
* `p:speedDial`: without `showIcon` the button draws the theme icon `--p-speeddial-show-icon` instead of `pi pi-plus`;
  `showIcon` / `hideIcon` still set icons per instance.
* `p:menuButton` without `icon` and the dropdown of `p:splitButton` draw the theme icons `--p-button-dropdown-icon` /
  `--p-splitbutton-dropdown-icon` instead of `ui-icon-triangle-1-s` (`MenuButton.ICON_CLASS` changed its value).

### jQuery UI

PrimeFaces does not ship jQuery UI (and jQuery UI Touch Punch) anymore. `$.ui`, `$.widget`, `$.effects`,
`$.position`, `$.ui.keyCode`, `$.fn.uniqueId`, `$.fn.scrollParent`, the `:data()` selector and the jQuery UI widgets
(slider, selectable, ...) are not available anymore. Only on pages with `p:fileUpload`, the jQuery UI widget factory
bundled with the blueimp file upload plugin still defines `$.widget`, `$.Widget` and a partial `$.ui`, so `$.ui` does
not detect jQuery UI reliably:

* Drag and drop, sorting and resizing are PrimeFaces' own implementation based on pointer events (mouse, pen and touch
  without Touch Punch): `PrimeFaces.interactions`. The attributes of `p:draggable`, `p:droppable` and `p:resizable`
  are unchanged. Replace the jQuery UI plugins with the PrimeFaces calls, the options, callbacks, `ui` arguments and
  events (`dragstart`, `drop`, `sortupdate`, ...) stay the same; the CSS classes have the `p-` prefix
  (`p-draggable-dragging`, `p-droppable-hover`, `p-sortable-placeholder`, `p-resizable-handle`, ..., see
  [Style classes](#style-classes)):

  | Before (jQuery UI) | Now |
  | --- | --- |
  | `$(element).draggable(options)` | `PrimeFaces.interactions.draggable($(element), options)` |
  | `$(element).droppable(options)` | `PrimeFaces.interactions.droppable($(element), options)` |
  | `$(element).sortable(options)` | `PrimeFaces.interactions.sortable($(element), options)` |
  | `$(element).resizable(options)` | `PrimeFaces.interactions.resizable($(element), options)` |
  | `$(element).sortable('disable')` (`enable`, `destroy`) | `PrimeFaces.interactions.disable($(element), 'sortable')` |
  | `$(element).sortable('instance')` | `PrimeFaces.interactions.instance($(element), 'sortable')` |
  | `$(element).sortable('option', 'axis', 'y')` | `PrimeFaces.interactions.instance($(element), 'sortable').option('axis', 'y')` |
  | `$(element).sortable('cancel')` (`refresh`) | `PrimeFaces.interactions.instance($(element), 'sortable').cancel()` |
  | `$.ui.ddmanager.current` | `PrimeFaces.interactions.dragDrop.current` |

  The jQuery plugins `$.fn.draggable`, `$.fn.droppable`, `$.fn.sortable` and `$.fn.resizable` do not exist anymore.
  Not supported anymore are the `selectable` interaction and rarely used jQuery UI features:
  * all interactions: `delay`, `cursorAt`, `scrollSensitivity` / `scrollSpeed` (fixed to 20 pixels), `classes`
    (except for droppable), `addClasses`, the `widget` method and `$.ui.plugin`.
  * draggable: `iframeFix` (not needed anymore, the pointer is captured while dragging; for the same reason the
    `iframeFix` property of the Dialog widget, the overlay over iframes while resizing, is gone), `refreshPositions`,
    `dropBehaviour` and the snap events. `connectToSortable` works as before: the placeholder moves in the sortable,
    the element (or the clone of the `clone` helper) is inserted on drop and `over`, `change`, `receive` and `update`
    are triggered. `cancel()` ends the drag without a drop (jQuery UI dropped on the droppable under the pointer).
  * sortable: `containment`, `grid`, `tolerance`, `dropOnEmpty: false`, `forceHelperSize`, `items` as function,
    `connectWith` as array, `placeholder` as object, the methods `serialize`, `toArray` and `refreshPositions`; a
    callback returning `false` does not cancel the sorting. Like for draggable, the `clone` helper has no `id`.
  * resizable: `autoHide`, `cancel`, `handles` as object and changing `ui.size` in the `resize` callback.

  The `remove` event, which the jQuery UI widget factory triggered on removed elements, is still triggered (e.g.
  `$(element).on('remove', fn)`), and the events of the interactions (e.g. `resize`) bubble as before. Like with the
  widget factory, `remove` is triggered on each removed element that has a handler and does not bubble anymore (the
  former PrimeFaces patch of `$.fn.remove` let it bubble): a handler of an ancestor is not called when only a
  descendant is removed.
* `$(element).position(options)` (with `my`, `at`, `of`, ...) is replaced by
  `PrimeFaces.utils.position($(element), options)` with the same options. `$.fn.position()` without arguments is the
  plain jQuery method again; `$.position` and `$.ui.position` are not available anymore.
* `$(element).effect(...)` and the effect variants of `show`, `hide` and `toggle` (e.g. `$(element).hide('blind')`)
  are replaced by `PrimeFaces.effects.run`, `PrimeFaces.effects.show`, `PrimeFaces.effects.hide` and
  `PrimeFaces.effects.toggle`, e.g. `PrimeFaces.effects.hide($(element), 'blind', { duration: 500, complete: fn })`.
  `$.effects` and color animations with `$.fn.animate` (`backgroundColor`, ...) are not available anymore.
  The jQuery animations (`fadeIn`, `slideUp`, `show(400)`, ...) and the jQuery UI easing names
  (`easeInOutCirc`, ...) still work.
* The effects (`p:effect`, `showEffect` / `hideEffect` / `effect` of the components) are implemented with the Web
  Animations API. They look the same in most cases, but do not wrap the element or insert placeholders anymore: only
  `blind` and `fold` move the surrounding layout during the effect (with a negative margin), the other effects move it
  when they are finished, `scale` and `puff` scale with the CSS `scale` property (`scale` ignores the `scale` option,
  the whole element is scaled), `size` ignores the `origin`, `scale` and `restore` options, and the `direction`
  option of `scale` now scales in the given direction (`horizontal` scales the width). The element of the `transfer`
  effect has the class `p-effect-transfer` instead of `ui-effects-transfer`. `fade` without `mode` (e.g.
  `<p:effect type="fade">`) now toggles the element as documented: a visible element stays hidden after the effect
  and a hidden one is shown (before, a visible element reappeared and a hidden one did nothing).
  As the effects are no jQuery animations anymore, `$(element).stop()` / `finish()` do not end a running effect, use
  `PrimeFaces.effects.stop(element)`; the `:animated` selector still matches an element with a running effect.
* The `:focusable` and `:tabbable` selectors are provided by PrimeFaces and still work.
* `p:signature` draws with pointer events, the jQuery plugin `$(element).signature(...)` was removed (use the widget,
  e.g. `PF('signature').clear()` or `PF('signature').toJSON()`) and the class `kbw-signature` is now `p-signature`.
  The plugin methods `toSVG()` and `toDataURL()` have no widget counterpart; use the `base64Value` attribute or
  `PF('signature').canvas[0].toDataURL()`.
  The guideline uses the documented default `guidelineOffset="25"`; before, the plugin default of 50 was used when the
  attribute was not set (or set to 25), so set `guidelineOffset="50"` to keep the old position.
* `p:datePicker` and `p:galleria` are plain PrimeFaces widgets without the jQuery UI widget factory: the jQuery plugins
  `$(element).datePicker(...)`, `$(element).galleria(...)` and the instances in `jq.data()` (`primeDatePicker`,
  `prime-galleria`) are not available anymore, nor is the `primeGalleriaWidget` property of the Galleria widget. Call
  the methods on the widget instead, e.g. `PF('datePicker').setDate(date)`, `PF('datePicker').formatDateTime(date)`,
  `PF('galleria').next()` or `PF('galleria').setActiveIndex(index)` (formerly
  `PF('galleria').primeGalleriaWidget.setState({ activeIndex: index })`). The DatePicker options with the defaults
  applied are in `PF('datePicker').options`. The DatePicker callbacks `onFocus`, `onBlur`,
  `onInput`, `onChange`, `onSelect`, `onTodayButtonClick` and the other internal callbacks of the jQuery plugin were
  removed; `preShow`, `dateTemplate`, `weekCalculator`, `onMonthChange` and `onYearChange` stay. Their `this` (and
  the argument of `preShow`) is now the widget instead of the plugin instance; `inputfield` and `container` of the
  plugin are still available as deprecated aliases of `input` and `jq`, `PF('datePicker').jqEl` is deprecated too
  (use `input`) and `showOverlay()` / `hideOverlay()` are internal (use `show()` / `hide()`).
  `PF('datePicker').options.minDate` / `maxDate` hold the parsed dates and can be changed at runtime, followed by
  `PF('datePicker').updatePanel()`.
  The time picker now fires the `change` / `dateSelect` events exactly once per change (before, the first AM/PM
  toggle or a change by keyboard before any mouse change fired nothing, and Enter / Space fired twice afterwards).
* `p:slider` has its own implementation:
  * `$(element).slider(...)` is not available anymore, use the widget methods (`PF('slider').getValue()`,
    `setValue(value)`, `getValues()`, `setValues(values)`, `enable()`, `disable()`).
  * The `onSlideStart`, `onSlide` and `onSlideEnd` callbacks get the same `ui` argument (`handle`, `handleIndex`,
    `value`, `values`), but the jQuery UI events `slidestart`, `slide`, `slidestop` and `slidechange` are not triggered
    on the element anymore. Like before, `onSlideStart` and `onSlide` cancel the slide with `event.preventDefault()`;
    returning `false` now cancels it too (before, the return value was ignored).
  * The slider only renders `p-slider`, `p-slider-horizontal` / `p-slider-vertical`, `p-slider-handle`,
    `p-slider-range` (`-min` / `-max`) and `p-state-disabled`; the jQuery UI classes `ui-widget`,
    `ui-widget-content`, `ui-widget-header`, `ui-corner-all`, `ui-state-default`, `ui-state-hover`, `ui-state-focus`
    and `ui-state-active` are gone (use `:hover`, `:focus-visible` and `:active`).
  * The handles have `role="slider"` with the `aria-value*` attributes, and `readonly="true"` now prevents changes.
  * In range mode, each input (also an InputNumber or Spinner) moves its own handle.
* `p:galleria` with `autoPlay` and `circular="false"` stops the slideshow at the last item.

### jQuery plugins

* The resource `jquery/jquery-plugins.js` was removed. The jQuery extensions of PrimeFaces that were left in it
  (`$.fn.focus(delay)`, `$.fn.zIndex()`, the `:focusable` and `:tabbable` selectors and the `remove` event on removed
  elements, which destroys the widgets after AJAX updates) are part of `core.js` now, so they are available on every
  page with a PrimeFaces component (before, components that only loaded `core.js` did not get them). Remove
  `@ResourceDependency(library = "primefaces", name = "jquery/jquery-plugins.js")` and
  `<h:outputScript name="jquery/jquery-plugins.js" library="primefaces"/>` from your own components and pages,
  otherwise JSF reports the missing resource.
* The jQuery Browser plugin was removed, `$.browser` and `window.jQBrowser` are not available anymore. Use
  `PrimeFaces.env.browser` (e.g. `PrimeFaces.env.browser.safari`) or `PrimeFaces.env.mobile` / `ios` / `android`
  instead. It detects the current browsers and platforms only: the flags of Internet Explorer and legacy browsers and
  platforms (`msie`, `rv`, `iemobile`, `opera`, `windows phone`, `blackberry`, `bb`, `playbook`) and the `uaMatch`
  function are gone.
* The jQuery Caret Position plugin was removed, `$.fn.getCaretPosition`, `getCursorPosition`, `getComputedStyle`,
  `cloneStyle` and `cloneAllStyle` are not available anymore. Use `element.selectionStart` for the cursor position.
* The jQuery plugin rangyinputs was removed, `$.fn.getSelection`, `setSelection`, `replaceSelectedText`, `insertText`,
  ... are not available anymore. Use `PrimeFaces.utils.getTextSelection(element)`,
  `PrimeFaces.utils.setTextSelection(element, start, end)` and `PrimeFaces.utils.replaceTextSelection(element, text)`
  or the native `selectionStart`, `setSelectionRange()` and `setRangeText()` of the input.
* The jQuery Mousewheel plugin was removed, the `mousewheel` event of jQuery does not normalize the wheel anymore; use
  the native `wheel` event (e.g. `$(element).on('wheel', e => e.originalEvent.deltaY)`).
* `$.fn.disableSelection` and `$.fn.enableSelection` (formerly jQuery UI) were removed, use the CSS
  `user-select: none` instead.
* The jQuery Knob plugin was removed, `p:knob` draws its own SVG now: `$(element).knob(...)` is not available
  anymore, use the widget (`PF('knob').setValue(value)`, `getValue()`, `increment()`, `decrement()`, `enable()`,
  `disable()`). The markup is `div.p-knob > input[type=hidden] + svg.p-knob-svg` (the `div` has the client id,
  `style` and `styleClass`); the colors come from the new `--p-knob-*` tokens of the theme (the value arc is the
  primary color now), `foregroundColor` / `backgroundColor` set `--p-knob-value-background` /
  `--p-knob-range-background`. The `colorTheme` attribute (`KnobBase#getColorTheme()`) and its themes (aristo,
  hot-sneaks, ...) were removed, use the tokens. A relative `width` / `height` (e.g. `50%`) is a CSS length now. The knob can be changed with the
  keyboard too (arrow keys, Page Up / Page Down, Home / End) and `disable()` now also prevents changes by the pointer.
  Other options of jQuery Knob (`data-skin="tron"`, `data-angleoffset`, `data-anglearc`, `data-rotation`,
  `data-displayprevious`, `data-font`, ...) are not supported.
* The jScrollPane plugin was removed, `p:scrollPanel` has its own implementation: the content scrolls natively (mouse
  wheel, touch, keyboard) with hidden browser scrollbars, the themed bars follow it and can be dragged.
  `$(element).jScrollPane(...)` and the `jsp` property of the widget are not available anymore, use the widget
  (`PF('panel').scrollTo(x, y)`, `scrollX(x)`, `scrollY(y)`, `redraw()`). The markup is rendered by the server:
  `div.p-scrollpanel > div.p-scrollpanel-content + div.p-scrollpanel-track-y / -track-x > div.p-scrollpanel-bar`
  (formerly `ui-scrollpanel-container`, `-vbar`, `-hbar`, `-drag`, `-cap` and the `jsp*` classes). The bars follow
  changes of the content and of the size automatically, also in a container that becomes visible later. The padding
  is on the content now, the content is focusable only while it overflows. The element that scrolls is the
  `div.p-scrollpanel-content`, not the `div.p-scrollpanel`, and the children are inside it (like before, when
  jScrollPane moved them into its own elements): `PF('panel').jq.scrollTop(...)` and selectors like
  `.p-scrollpanel > .child` do not work, use `scrollY(y)` / `PF('panel').content` and
  `.p-scrollpanel-content > .child`. The unused style class constants of
  `ScrollPanel` (`SCROLL_PANEL_CONTAINER_CLASS`, `_WRAPPER_`, `_HBAR_`, `_VBAR_`, `_HANDLE_`, the border, grip and icon
  constants) were removed.
* The jQuery KeyFilter plugin was removed, `$.fn.keyfilter` is not available anymore; use `p:keyFilter`. Its masks are
  in `PrimeFaces.widget.KeyFilter.masks` (formerly `$.fn.keyfilter.defaults.masks`). `p:keyFilter` checks the typed
  characters on `beforeinput` instead of `keypress` now, so it also works with the virtual keyboards of mobile devices;
  of a text with several characters (e.g. an autocompletion of the keyboard) only the allowed characters are inserted,
  and the characters of a text composed with an input method editor (IME) that do not pass the filter are removed when
  the composition ends.

### Type declarations

The namespace of the TypeScript types of the client-side API (NPM package `primefaces`) was renamed from `PrimeType`
to `PrimeFacesTypes`. Values stay in `PrimeFaces`, e.g. replace `PrimeType.widget.DeferredWidgetCfg` with
`PrimeFacesTypes.widget.DeferredWidgetCfg` and `PrimeType.Widget<"CommandButton">` with
`PrimeFacesTypes.Widget<"CommandButton">`. The types of the new modules are in the namespace of their module:
`PrimeFacesTypes.effects` (`PrimeFaces.effects`), `PrimeFacesTypes.interactions` (`PrimeFaces.interactions`) and
`PrimeFacesTypes.utils` (e.g. `PositionOptions` of `PrimeFaces.utils.position`).

### AjaxExceptionHandler

The `onexception` callback now receives the same arguments for exceptions handled on the server and on the client:
`type`, `message` and `timestamp`. On the client, the arguments were previously named `errorName` and `errorMessage`,
so replace e.g. `onexception="alert(errorMessage)"` with `onexception="alert(message)"`.
On the server, `timestamp` was previously misspelled as `timestampp`.

### Calendar

`p:calendar` (based on the jQuery UI datepicker and the jQuery Timepicker Addon) was removed, use `p:datePicker`
instead. The jQuery UI datepicker and the timepicker addon are no longer shipped, so `$.datepicker`,
`$.fn.datetimepicker` and `$.fn.timepicker` are not available anymore. The selenium component
`org.primefaces.selenium.component.Calendar` was removed as well.

### DatePicker

* The `timeOnly` DatePicker now moves focus to the popup when opened if `showIcon` is disabled.
* Enter in a time input of the popup (`timeInput`) only closes the popup, it does not reach the form anymore (e.g. a
  `p:defaultCommand`). With `hourFormat="12"`, an hour typed into the time input stays in the current half of the day.
* The widget is one class now, the methods `bindDateSelectListener`, `bindViewChangeListener`, `bindCloseListener`,
  `bindClearButtonListener`, `bindPanelCreationListener`, `fireDateSelectEvent` and `fireCloseEvent` of the former
  wrapper widget do not exist anymore and can't be overridden; use the `dateSelect`, `viewChange` and `close` behaviors
  (e.g. `<p:ajax event="dateSelect" onstart="..."/>`) or the `onMonthChange` / `onYearChange` callbacks.
* The message keys were renamed from `primefaces.calendar.*` to `primefaces.datepicker.*`. Rename them in your own
  message bundles:

| Old key | New key |
| --- | --- |
| `primefaces.calendar.INVALID` | `primefaces.datepicker.INVALID` |
| `primefaces.calendar.MIN_DATE` | `primefaces.datepicker.MIN_DATE` |
| `primefaces.calendar.MAX_DATE` | `primefaces.datepicker.MAX_DATE` |
| `primefaces.calendar.OUT_OF_RANGE` | `primefaces.datepicker.OUT_OF_RANGE` |
| `primefaces.calendar.DATE_INVALID_RANGE_MESSAGE_ID` | `primefaces.datepicker.DATE_INVALID_RANGE_MESSAGE_ID` |

* `org.primefaces.component.calendar.BaseCalendarRenderer` was renamed to
  `org.primefaces.component.datepicker.BaseDatePickerRenderer`; custom renderers extending it need the new name.

### GMap

Markers are now rendered as `google.maps.marker.AdvancedMarkerElement` instead of the deprecated `google.maps.Marker`,
see the [Google migration guide](https://developers.google.com/maps/documentation/javascript/advanced-markers/migration).

* Advanced markers require a map ID. The new `mapId` attribute defaults to `DEMO_MAP_ID`, which is for testing only.
  Set your own map ID in production: `<p:gmap mapId="YOUR_MAP_ID" ... />`. A map ID can change the map styling.
* `Marker` properties `animation`, `cursor`, `flat` and `shadow` are deprecated and ignored.
* `MarkerLabel` is rendered as the glyph of the default pin, only `text` and `color` are used.
* `PF('map').cfg.markers` now contains `AdvancedMarkerElement` instances. Use the `position`, `title` and `map`
  properties instead of `getPosition()`, `setTitle()` and `setMap()`.
* Markers created in your own JavaScript must be `AdvancedMarkerElement` instances. When loading Google Maps with a
  script tag, add `libraries=marker` to the script URL.

### TreeTable Exporter

* `pageOnly` now exports exactly the rows displayed on the current page: the root children of the current page together
  with their expanded descendants. Children of collapsed nodes are no longer exported, and without a paginator every
  displayed row is exported regardless of `rows`. `selectionOnly` now exports the selected nodes instead of the root node.
* Custom `TreeTableExporter` subclasses: every row is now exported through
  `exportRowData(FacesContext, TreeTable, Object data)`. The index based `exportRow(FacesContext, TreeTable, int)` is
  deprecated and no longer called, so move overrides of it to `exportRowData`.

### MegaMenu

`activeIndex` now identifies a persistent current section, rendered with `p-menuitem-selected` and `aria-current="page"`.
Its underline remains visible while other roots are hovered or opened. The selected enabled root is the default keyboard tab stop.
Custom styles for persistent selection should target `.p-menuitem-selected > .p-menuitem-link`; `p-menuitem-active` remains transient.

An omitted `activeIndex` no longer implicitly highlights the first root. Set `activeIndex="0"` to select it explicitly.
Negative indexes (including `-1`, which previously selected the last root) and out-of-range indexes select nothing.
Indexes count rendered enabled root links, excluding disabled items, separators and facets.

### Tree / TreeTable checkbox selection

Checkbox selection no longer changes the selection of a node with `selectable="false"` (`TreeNode#setSelectable(false)`),
in the browser as well as on the server.

* `CheckboxTreeNode#setSelected` no longer counts non-selectable children when it propagates the selection up: a parent
  is selected once all of its selectable children are, and a parent without selectable children keeps its state. Code
  that calls `setSelected` and relies on the previous parent state needs to be adjusted.
* A non-selectable node is accepted in the submitted selection only if it was selected before, and in checkbox mode a
  previously selected non-selectable node stays selected. This relies on the `selection` attribute being bound, as only
  then is the selection preselected by the model available on submit.
* TreeTable with `propagateSelectionDown="false"` no longer selects the descendants of the clicked node on the server.

### TriStateManyCheckbox (from PrimeFaces Extensions)

`pe:triStateManyCheckbox` was moved from PrimeFaces Extensions to PrimeFaces as `p:triStateManyCheckbox`, with the same
attributes and the same value (a Map of the item values to the states). Only the `change` event is supported
(`event="valueChange"` or DOM events like `click` must become `change`), the markup, the style classes and the widget
(`PrimeFaces.widget.TriStateManyCheckbox`) changed, see [TriStateManyCheckbox](../17_0_0/components/tristatemanycheckbox.md?id=migration-from-primefaces-extensions).
