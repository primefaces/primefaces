# Migration guide 16.0.0 -> 17.0.0

## Breaking Changes

### AjaxExceptionHandler

The `onexception` callback now receives the same arguments for exceptions handled on the server and on the client:
`type`, `message` and `timestamp`. On the client, the arguments were previously named `errorName` and `errorMessage`,
so replace e.g. `onexception="alert(errorMessage)"` with `onexception="alert(message)"`.
On the server, `timestamp` was previously misspelled as `timestampp`.

### DatePicker

The `timeOnly` DatePicker now moves focus to the popup when opened if `showIcon` is disabled.

### GMap

Markers are now rendered as `google.maps.marker.AdvancedMarkerElement` instead of the deprecated `google.maps.Marker`,
see the [Google migration guide](https://developers.google.com/maps/documentation/javascript/advanced-markers/migration).

* Advanced markers require a map ID. The new `mapId` attribute defaults to `DEMO_MAP_ID`, which is for testing only.
  Set your own map ID in production: `<p:gmap mapId="YOUR_MAP_ID" ... />`. A map ID can change the map styling.
* `Marker` properties `animation`, `cursor`, `flat` and `shadow` are deprecated and ignored.
* `MarkerLabel` is rendered as the glyph of the default pin, only `text` and `color` are used.
* `PF('map').cfg.markers` now contains `AdvancedMarkerElement` instances. Use the `position`, `title` and `map`
  properties instead of `getPosition()`, `setTitle()` and `setMap()`.
* Markers created in your own JavaScript must be `AdvancedMarkerElement` instances. When loading Google Maps with a
  script tag, add `libraries=marker` to the script URL.

### Renderers are wrapped

PrimeFaces now installs a `RenderKitFactory` (`org.primefaces.renderkit.PrimeRenderKitFactory`). Its render kit hands
out every PrimeFaces renderer, meaning every `org.primefaces.renderkit.CoreRenderer`, inside a
`org.primefaces.renderkit.PrimeRendererWrapper`. The wrapper resets the iteration state of components which implement
`org.primefaces.component.api.IterationCleanupAware` after `decode` and after `encodeEnd`, so that a row index, a row
key or an iteration variable never outlives the phase which set it.

Renderers of the Faces implementation and of other component libraries are handed out untouched.

This only matters if you cast the result of `RenderKit#getRenderer` to a PrimeFaces renderer type:

```java
// throws ClassCastException as of 17.0.0
DataTableRenderer renderer = (DataTableRenderer) context.getRenderKit()
        .getRenderer(DataTable.COMPONENT_FAMILY, DataTable.DEFAULT_RENDERER);
```

`PrimeRendererWrapper` implements `jakarta.faces.FacesWrapper`, so unwrap it:

```java
DataTableRenderer renderer = ComponentUtils.getUnwrappedRenderer(context,
        DataTable.COMPONENT_FAMILY, DataTable.DEFAULT_RENDERER);
```

`ComponentUtils#getUnwrappedRenderer` already existed and works on both versions.

### TreeTable Exporter

* `pageOnly` now exports exactly the rows displayed on the current page: the root children of the current page together
  with their expanded descendants. Children of collapsed nodes are no longer exported, and without a paginator every
  displayed row is exported regardless of `rows`. `selectionOnly` now exports the selected nodes instead of the root node.
* Custom `TreeTableExporter` subclasses: every row is now exported through
  `exportRowData(FacesContext, TreeTable, Object data)`. The index based `exportRow(FacesContext, TreeTable, int)` is
  deprecated and no longer called, so move overrides of it to `exportRowData`.
