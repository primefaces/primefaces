# PrimeFaces Themes (design tokens)

Developer notes of the PrimeFaces theming. The user documentation is `docs/17_0_0/core/theming.md`.

Design token based themes. Pure CSS, no SASS, everything customizable through CSS variables, light and dark mode built in.
Token naming follows the PrimeUIX convention (`--p-primary-color`, `--p-form-field-background`, `--p-button-primary-background`, ...).

The CSS is part of the `primefaces` module: the CSS of the components lives next to their widgets in `packages/`, the
themes (the tokens of each preset) in `themes/`. Since PrimeFaces 17 these are the only themes; the legacy themes
(`primefaces-themes`, saga, arya, ...) were removed.

What changed for applications compared to the legacy themes:
- **Customization with tokens:** application CSS that overrides PrimeFaces styles by selector and specificity may need
  adjustments; colors, radius, density, icons etc. are CSS variables. There is no SASS / theme designer anymore.
- **Icons:** the icons a component draws itself come from icon tokens (`--p-icon-*`, `--p-<component>-...-icon`), not
  from PrimeIcons / Font Awesome classes ([#15278](https://github.com/primefaces/primefaces/issues/15278)):
  - the JSF attributes for these icons are removed without replacement (e.g. `p:panel closeIcon / collapsedIcon /
    expandedIcon / menuIcon`, `p:rowToggler expandIcon / collapseIcon`, `p:spinner upIcon / downIcon`,
    `p:chip removeIcon`, `p:breadCrumb homeIcon`, ...; full list in the migration guide). Configure them in CSS.
  - renderers emit semantic icon classes (`p-icon p-close-icon p-panel-close-icon`) instead of the legacy jQuery UI
    icon classes (`ui-icon-triangle-1-e`, ...), widgets switch states (`aria-expanded`) instead of icon classes.
- **Style classes:** the former jQuery UI style classes `ui-*` are `p-*` now (except the Grid CSS `ui-g` / `ui-grid` and
  the classes the jQuery keypad of p:keyboard renders; the datePicker panel is `p-datepicker-panel`).
  jQuery UI is removed already (own effects, position, slider and drag and drop / sorting / resizing interactions with
  compatible options), `p:calendar` is removed in favor of `p:datePicker`.

Each breaking core change gets its entry in the migration guide (`docs/migrationguide`) when it is implemented.

## Usage

```xml
<context-param>
    <param-name>primefaces.THEME</param-name>
    <param-value>aura</param-value>   <!-- aura (default) | lara | nora | metal | glass | none (or empty) -->
</context-param>
```

Everything else is plain CSS in the application:

```css
:root {
    color-scheme: dark;                         /* light | dark | "light dark" (= system, default) */
    --p-primary-base: var(--p-indigo-500);      /* or any color, e.g. #0a7d5a */
    --p-button-border-radius: 2rem;             /* any component token */
}

.sidebar { color-scheme: dark; }                /* dark area inside a light page */

.admin[data-p-scope] { --p-primary-base: var(--p-red-600); }   /* scoped primary color */
```

```html
<html data-p-density="compact">                 <!-- compact | comfortable | normal (spacing of forms, lists, tables, ...) -->
```

- The text color on the primary color (`--p-primary-contrast-color`) follows the primary color: white, or dark text
  for light primary colors (lime, amber, yellow), so any `--p-primary-base` stays readable. The light mode threshold
  (OKLCH lightness 0.75) keeps white text on green / emerald / teal / cyan 500, like PrimeUIX.
- The primary palette 50-950 is mixed in OKLCH from `--p-primary-base` (even steps, no gray mid tones).
- Density: `themes/density/<preset>.css` scales the spacing tokens of the preset (0.75 / 1.25, generated by
  `build/scripts/themes/generate-density.mjs`). It works on any element, also nested and inside scopes; `normal` restores the preset.

Everything lives in cascade layers (`primefaces.tokens, primefaces.vendor, primefaces.components,
primefaces.behaviors`), so unlayered application CSS always wins, without `!important` and regardless of specificity
(except against the few `!important` declarations of PrimeFaces, see "Known limitations"). Each stylesheet of PrimeFaces starts with that layer statement, so the order is the same whichever is loaded first.

A page renders:
- `primefaces-<theme>:theme.css` (the `primefaces.THEME` context parameter, first in the head): the tokens of the theme.
  A custom theme is a `META-INF/resources/primefaces-<name>/theme.css` with the tokens (and the layer statement).
- `primefaces:components.css`: icon set, base interaction CSS and the CSS of all components of `components.js`, the same for
  every theme (stays cached when the theme changes).
- the CSS of lazily loaded components with their JS, e.g. `primefaces:schedule/schedule.css` (FullCalendar + p:schedule),
  `texteditor/texteditor.css` (Quill), `timeline/timeline.css` (vis-timeline).

PrimeFaces does not compress resources: enable gzip / brotli in the server (`components.css` ~360 KB minified; a theme
~210 KB; gzip ~47 KB + ~25 KB). PrimeIcons are still loaded (unless `primefaces.PRIME_ICONS` is false) for the icons applications
set themselves (`icon="pi pi-check"`), in the `primefaces.vendor` layer (component CSS and application CSS win
over the `.pi` rules).

## Structure

```
primefaces/src/main/frontend/
  themes/<theme>.css               entry of a theme (aura, lara, nora, metal, glass): preset + density, built to
                                   META-INF/resources/primefaces-<theme>/theme.css
  themes/presets/<theme>.css       all tokens of a theme: primitive, semantic and one block per component; the PrimeUIX
                                   tokens and the PrimeFaces tokens (components/parts PrimeUIX does not have) side by side.
                                   metal (graphite / brushed aluminium, black metal in dark mode) and glass (Apple
                                   Liquid Glass style) are own presets, started from Aura
  themes/density/<theme>.css       compact / comfortable spacing of a preset (generated)
  packages/components/index.css    components.css: layer order, icon set, interaction CSS, then base -> shared -> components
                                   -> behaviors (alphabetical inside each group, see the comments there)
  packages/components/src/icons/lucide.css   the icon set: one --p-icon-* token per meaning (close, expanded, ...)
  packages/components/src/base/*.css         p-widget, p-state-*, core helpers, grid (ui-g), interaction base rules,
                                             document (page, reduced motion / transparency, print), scrollbar, backdrop (Glass)
  packages/components/src/<widget>/*.css     one file per tag next to its widget (datatable/datatable.css,
                                             forms/selectonemenu.css, menu/tieredmenu.css, ...); building blocks of
                                             several components: forms/inputfield.css, forms/checkbox.css,
                                             forms/radiobutton.css, forms/inputgroup.css, badge/badge.css,
                                             paginator/paginator.css, menu/menu.base.css
  packages/components/src/{dragdrop,resizable,sticky}/*.css   behaviors (layer primefaces.behaviors), also
  packages/components/src/base/hidden.css                     p-hidden (wins over every display of the components)
  packages/<name>/<name>/index.css + src/<name>.css           components whose widget is its own package (not in
                                             components.js): CSS next to the widget, loaded with it by the
                                             @ResourceDependency of the component (clock, colorpicker,
                                             datepicker, diagram, dock, fileupload, galleria, imagecompare,
                                             imagecropper, inputotp, inputphone, keyboard, knob, lifecycle, log,
                                             mindmap, organigram,
                                             schedule, scrollpanel, signature, stack, terminal, texteditor,
                                             timeline, tristatemanycheckbox) with their third-party CSS
  build/scripts/bundle.mjs                   esbuild: bundles the index.css files and the themes, inlines the icons
  build/scripts/themes/check.mjs             conventions check, runs before the build (see below)
  build/scripts/themes/generate-density.mjs  generates themes/density/*.css from the presets (--check: up to date)
  build/scripts/themes/export-tokens.mjs     exports the tokens in the W3C Design Tokens format (DTCG) to
                                             primefaces/target/tokens/ (published as primefaces-<version>-tokens.zip)
```

- The presets are the source of truth and are edited by hand. They started from PrimeUIX 3.0.1 (Aura, Lara, Nora) but
  are not synced with PrimeUIX: PrimeUIX was the template, the presets deviate where that is right (e.g. form fields
  follow the global focus ring in all presets).
- All tokens follow the PrimeUIX naming (`--p-<component>-<section>-<token>`), reference other tokens instead of literal
  colors and live in the block of their component, in all presets.
- Differences to PrimeUIX: the primary palette 50-950 is derived from `--p-primary-base` via `color-mix(in oklch)`,
  `--p-primary-contrast-color` is computed from the primary color, every semantic/component token is declared on
  `:root, [data-p-scope]`. The build (`scopedTokensPlugin` in `bundle.mjs`) splits these blocks: tokens with a literal
  value go to `:root` only and inherit into scopes (density, application overrides on `:root`), tokens that reference
  other tokens are declared on `:root, [data-p-scope]`, so they resolve against the values of a scope, and those that
  lead to a density token (`themes/density/<preset>.css`) also on `[data-p-density]`. It fails on a block it cannot
  split (one token per line).
- `build/scripts/themes/check.mjs` enforces: every `var(--p-*)` is defined, all presets define the same tokens, no
  literal colors outside the presets and the icon set, no malformed values, and every
  preset token is used (an unused token is deleted, not kept for later), no container queries, no
  var() cycles (presets + component CSS), no values that are invalid where they are used (size without unit, unitless 0
  in calc(), "inset none", several widths in a border shorthand).

The CSS uses native nesting (states, variants and children nested under their component; selector lists with
different specificity stay flat).

The build (`yarn run build:bundle`, run by Maven through `frontend-maven-plugin`) = `build:themes:check` +
`build/scripts/bundle.mjs` + `build:themes:tokens`:
- every `index.css` → `META-INF/resources/primefaces/<package>.css` (`components.css`, `schedule/schedule.css`, ...),
  each `@import` puts its file into its cascade layer (`layer(primefaces.components)`).
- `themes/<theme>.css` → `META-INF/resources/primefaces-<theme>/theme.css`.
- `url("lucide-static/icons/x.svg")` in the icon set is inlined as data URI (`?fill` fills the outline).
- CSS imported by JavaScript dependencies (e.g. FullCalendar) is dropped: third-party CSS comes from the `index.css`
  files only, in `@layer primefaces.vendor`.
- `NODE_ENV=development` builds readable CSS.
- `primefaces/target/tokens/<theme>.light|dark.tokens.json` (attached as `primefaces-<version>-tokens.zip`): the tokens in the DTCG format (for Figma / Tokens Studio /
  Style Dictionary), light-dark() resolved per file, `var()` as aliases, color-mix / relative colors / calc resolved,
  the CSS value in `$extensions["org.primefaces.css"]`, density values in `$extensions["org.primefaces.density"]`.
- After changing a preset: `yarn run build:themes:density` regenerates the density files.

## Presets

- The PrimeUIX `timeline` tokens style p:chronoline (`--p-chronoline-*`); `--p-timeline-*` are the tokens of the
  vis-timeline based p:timeline.
- Tokens of PrimeUIX features PrimeFaces does not have were deleted. When such a feature comes (see "Modern look and
  feel" below), its tokens are added in all presets; PrimeUIX 3.0.1 is the reference for names and values.
- **Metal** (`themes/presets/metal.css`, not a PrimeUIX preset): graphite and brushed aluminium in light mode, black metal in
  dark mode, the focus ring in the primary color (graphite by default). Everything is token values:
  - Metal edge lit from above: a background token with a face layer (`padding-box`) and an edge layer (`border-box`),
    border color `transparent` (buttons, toggleSwitch). The transparent border becomes visible in the forced colors
    mode. Form fields keep a real border (hover / focus border colors keep working).
  - `light-dark()` only takes colors, so the gradients switch per mode with `light-dark()` in their color stops.
  - PrimeFaces tokens for it (neutral in the other presets): `--p-button-texture` (layer above the background, Metal:
    SVG noise = brushed grain), `--p-button-shadow` (machined), `--p-button-active-shadow` / `--p-button-active-offset`
    (pressed), `--p-button-label-shadow` / `--p-button-outlined-label-shadow` (engraved labels),
    `--p-button-outlined-background`, `--p-toggleswitch-handle-shadow`.
  - Turned metal knobs: `conic-gradient` on the toggleSwitch / slider handles; the toggleSwitch icon is 60% of the knob.
  - Severity buttons are anodized metal (the metal face / edge tinted in the severity color, 700 shades with white text
    in light mode, 400 with dark text in dark mode). Per mode gradient direction without duplicating the token:
    `color-mix(in oklch, B, light-dark(black, B) 22%)` darkens only in light mode (mixing a color with itself keeps it).
  - Selection (highlight) is graphite; areas that are only marked (schedule today, dashboard / drag & drop hover) use a
    subtle tint instead.
  - Contrast: interactive edges >= 3:1 (WCAG 1.4.11), placeholder / muted text >= 4.5:1, selected vs. unselected
    (graphite vs. aluminium) clearly distinct.
- **Glass** (`themes/presets/glass.css`, not a PrimeUIX preset): Apple Liquid Glass style.
  - Layers like the Apple HIG: the content layer (cards, panels, tables, accordion) is an almost opaque surface
    (72%), the floating controls layer is glass: overlays, dialogs, menus, tooltips, growl, the toolbar and buttons blur
    and saturate what lies behind them (`backdrop-filter`), with a light rim and a specular highlight on top. The modal
    mask blurs the page.
  - PrimeFaces tokens for it (neutral in the other presets): `--p-document-background` (page background, Glass: a soft
    wallpaper, glass needs something colorful behind it), `--p-overlay-backdrop-filter`,
    `--p-navigation-backdrop-filter` (toolbar), `--p-button-backdrop-filter`, `--p-mask-backdrop-filter`; applied in
    `packages/components/src/base/backdrop.css` with zero specificity. Dialog box and toolbar carry the filter on a `::before`
    behind them: on the element it would make the full viewport dialog container blur the whole page, and the toolbar the
    stacking context of its dropdowns (painted under the following content).
  - No backdrop filter on content containers: it makes the element the containing block of its absolutely / fixed
    positioned descendants (overlays inside it would be positioned wrong). Not on the menubar either: an element with a
    backdrop filter is the backdrop root of its descendants, its submenus would only blur what lies inside the bar.
    Nested overlays have the same limit, so the overlay backgrounds stay mostly opaque (86% light, 80% dark).
  - Apple system colors: the accessible variants in light mode (white text >= 4.5:1: blue #0071e3, green #1f7a35,
    orange #c93400, red #d70015, purple #8944ab, teal #0071a4), the bright ones for text in dark mode; Apple label /
    separator grays, system font stack.
  - The primary color is `--p-primary-base` (default Apple blue #0071e3) like in the other presets: primary text, focus
    ring, highlight and the primary button are shades of it (OKLCH offsets that give Apple's blues for #0071e3), the
    text on the primary button is white or dark depending on its lightness.
  - Controls: capsule buttons (neutral glass, tinted glass for primary / severities), iOS switch (accessible green,
    the off track has a border >= 3:1), segmented control for select buttons, iOS slider knob, macOS checkbox.
  - `backdrop-filter` costs GPU time; large blurred areas that move (scrolling under a sticky glass bar) are the
    expensive case.

## Icons

The icons the components draw themselves (toggle, close, sort, dropdown, pagination, ...) are SVGs, not an icon font.
The renderers emit semantic classes: `<span class="p-icon p-close-icon p-panel-close-icon">`
(generic, meaning, component + control: the PrimeFaces component name, also where the token block is named
after PrimeUIX, e.g. `p-growl-close-icon` for `--p-toast-close-icon`). `.p-icon` (base/common.css) shows `--_icon`
as mask of a `::before`, the color is `currentColor` and the size the font size; the component CSS maps its class to
the token once
(`.p-panel-close-icon { --_icon: var(--p-panel-close-icon); }`). Icons that change with the state have one class
(`p-panel-toggle-icon`), the CSS picks the token by the state of the component (`aria-expanded`,
`p-state-active`, ...); the widgets do not swap icon classes. Exceptions: the checkbox icon carries the state as
`p-checkbox-checked-icon` / `p-checkbox-indeterminate-icon` / `p-checkbox-crossed-icon` (tree / treeTable selection
read it), the dataTable / treeTable sort icon as `p-datatable-sort-asc-icon` / `-desc-icon` (the widget reads the
sort order from it, `aria-sort` is only set on one column). There are no JSF attributes for these icons, they are configured with CSS only, on two levels:

```css
/* the icon set: one token per meaning, packages/components/src/icons/lucide.css (Lucide, ISC) */
--p-icon-close: url(...);
--p-icon-collapsed: url(...);
--p-icon-expanded: url(...);

/* per component, in the component block of the presets: <component>-<control>[-<state>]-icon */
--p-tree-toggle-collapsed-icon: var(--p-icon-collapsed);
--p-tree-toggle-expanded-icon: var(--p-icon-expanded);
--p-tabs-close-icon: var(--p-icon-close);
```

Overriding (application CSS is unlayered and always wins):

```css
:root { --p-icon-close: url("/myapp/icons/close.svg"); }                    /* everywhere */
:root { --p-tree-toggle-collapsed-icon: url("data:image/svg+xml,..."); }    /* one component */
.sidebar { --p-icon-expanded: url("/myapp/icons/minus.svg"); }             /* one area */
```

- Any SVG works (Font Awesome, PrimeIcons, Tabler, ... all ship SVGs); only its shape is used, it is drawn in the text
  color.
- Use absolute paths or data URIs: a relative `url()` inside a custom property is resolved against the stylesheet that
  uses it (the theme resource), not the one that declares it.
- Directional icons are mirrored in RTL (`scale: -1 1`), so one icon per direction is enough.
- A complete other icon set is a CSS file with all `--p-icon-*` tokens, included after the theme.
- Full control per icon (font icon, size, color of one icon) with the classes: `.p-panel-close-icon::before { mask: none;
  background: none; content: "\f00d"; font-family: "Font Awesome 6 Free"; }`, `.p-close-icon` for every close icon.
- In the source, `url("lucide-static/icons/x.svg")` refers to the npm package and is inlined by `build/scripts/bundle.mjs`;
  `?fill` fills an outline icon (selected rating star).

## Motion

PrimeFaces tokens (PrimeUIX has durations only), in the semantic block of the presets:

```css
--p-transition-easing: cubic-bezier(0.4, 0, 0.2, 1);       /* something moves within the page */
--p-transition-easing-enter: cubic-bezier(0, 0, 0.2, 1);   /* something appears / slides in (decelerates) */
--p-transition-easing-exit: cubic-bezier(0.4, 0, 1, 1);    /* something disappears / slides out (accelerates) */
--p-overlay-enter-duration: 0.12s;                         /* connected overlays (.p-connected-overlay-*) */
--p-overlay-leave-duration: 0.1s;
```

Transitions that move something (sidebar, float label, toggle switch handle, speed dial, image compare, overlays) use
them together with the duration tokens; color / border / shadow changes keep the default curve. `build/scripts/themes/check.mjs` fails
on literal curves (`cubic-bezier()`, `ease*`) and literal durations in transitions (`linear`, `steps()` and `0s` are
allowed), so new transitions use the tokens.

Content that a widget inserts by ajax can animate in with CSS only: a keyframe animation runs when an element is
inserted (`@keyframes p-enter` in `base/common.css`, offset by `--_enter-offset`; also on page load). Used where new
content is the point: new messages of p:messages / p:message (`--p-message-enter-duration` / `-offset`, also from the client
side validation), the items of p:dataView on a layout switch and paging and the loaded items of p:dataScroller (not
with virtual scrolling) (`--p-dataview-content-enter-duration` / `-offset`). Deliberately not: dataTable / treeTable rows
(sorting / filtering often, a fade would only flicker; moving rows needs View Transitions in the core), dynamic tree
nodes (static nodes would not animate, `animate="true"` slides with jQuery already).

## User preferences and accessibility

`packages/components/src/base/document.css`:
- `prefers-reduced-motion`: `--p-transition-duration: 0s`, animations and transitions reduced to a minimum.
- `prefers-reduced-transparency`: all `--p-*-backdrop-filter` tokens `none` and `--p-toast-blur: 0px` (no blur behind
  floating layers).
- Native controls of the application (checkbox, radio, range, progress) use the primary color (`accent-color`), text
  selection the highlight colors.
- Print: light colors, no shadows, scrollable tables print all rows, overlays / growl / paginator hidden. Small state
  carrying elements (buttons, badges, tags, chips, checkbox / radio, toggleSwitch, slider, progressBar, selections) print
  their background (`print-color-adjust: exact`), browsers drop backgrounds but keep the (e.g. white) text color.
- Target size (WCAG 2.2, 24px): the small icon controls (chip / token remove, password toggle, breadcrumb home) get an
  invisible 24px hit area; checkboxes, radios and menu items rely on the spacing exception (as in PrimeUIX).

Icons stay visible in the Windows high contrast mode (`forced-color-adjust: none` on the icon, drawn in the forced text
color); focus rings are outlines, which the high contrast mode keeps.

Scrollbars (`packages/components/src/base/scrollbar.css`): the scroll containers of the components (dropdown / overlay lists, listboxes,
pickList / orderList, tree, scrollable dataTable / treeTable bodies, dialog, sidebar, ...) get thin themed scrollbars
(`scrollbar-width: var(--p-scrollbar-width)`, `scrollbar-color: var(--p-scrollbar-thumb-color)
var(--p-scrollbar-track-color)`, semantic tokens). The page and the application's own scroll areas keep the browser
scrollbars; to opt in, use the same two declarations (e.g. on `:root`). The rule has zero specificity (`:where()`);
`scrollbar-color` inherits into application content inside a dialog / sidebar; forced colors mode shows the system
scrollbars. p:scrollPanel draws its own bars over the natively scrolling content (`--p-scrollpanel-*`).

## Responsive components

Paginator (page links), dataTable / treeTable reflow, fileUpload (stacked layout), steps (titles), responsive pickList /
orderList (stacked) and full width selectOneButton / selectManyButton in `.p-fluid` react to the viewport
(`@media (max-width: 640px)`), like overlays, sidebars and the legacy `ui-g` grid. No container queries: inline-size
containment takes the width of an element from its parent only, so a component inside a shrink-to-fit parent (a dialog
without width, an inline-flex / auto table cell, a flex item without width) collapses to zero width.
`build/scripts/themes/check.mjs` rejects `container` / `container-type` in the component CSS.

## Known limitations

- Inside a `[data-p-scope]` element the tokens that reference other tokens are re-declared, so overrides of such
  tokens made on `:root` (colors, `--p-primary-base`, component tokens) must target `:root, [data-p-scope]` to reach
  into scopes. Literal tokens (sizes, paddings, `--p-icon-*`) are declared on `:root` only and reach them anyway.
- A custom theme (or the configurator CSS) written as one `:root, [data-p-scope]` block is not split like the built
  themes: its literal tokens are declared again in every scope, so a density or a `:root` override does not reach into
  scopes. Write literal tokens on `:root` (docs: "Custom theme").
- `!important` is used only where the CSS has to beat inline styles of jQuery / the widgets (dialog maximize / minimize,
  dataTable / treeTable reflow widths), for two structural rules (the header clone
  of scrollable dataTables has no height, #12908; buttons are never underlined, also not by `a:hover` of the
  application) and for the user preferences (reduced motion, print). An `!important` in a cascade layer beats unlayered
  application CSS even with `!important`, so these can not be overridden; hiding uses the behaviors layer
  (`base/hidden.css`) instead.
- Glass: nested overlays (submenus) only blur what lies inside their parent overlay (backdrop root), the overlay
  backgrounds stay mostly opaque for that.
- ColorPicker / Captcha read light or dark (`PrimeFaces.env.getThemeContrast(element)`) once when they are created; a
  later change of the color scheme does not switch them.
- Canvas based components (chart) take colors from JS options, not from CSS.
- Requires `light-dark()`, `color-mix()`, relative colors (`oklch(from ...)`), `:has()` and CSS nesting
  (Chrome 123, Firefox 128, Safari 18).
- Contrast of the primary color (Aura, Lara, Nora, like PrimeUIX / PrimeReact): white text on the default primary
  (emerald-500, Nora emerald-600) and primary colored text on white (links, active tab / step) reach ~2.5:1 (Nora
  ~3.9:1), below WCAG AA (4.5:1). Kept on purpose to stay close to PrimeReact. Applications that need AA use a darker
  primary in light mode, e.g. `:root { --p-primary-base: var(--p-emerald-700); }`. Metal (graphite) meets AA.
- The high contrast mode handling is not verified on Windows yet.
- Size: `components.css` is ~360 KB minified (~47 KB gzip) plus ~25 KB gzip per theme; the third-party CSS of the lazily loaded
  components (Quill, vis-timeline, FullCalendar, Coloris, jsPlumb, Cropper) is only loaded with them.
  The largest component file is `packages/datepicker/datepicker/src/datepicker.css`, loaded only with p:datePicker.

## Planned (PrimeFaces core)

These steps follow in the core:

**Other**
- `RatingRenderer` never renders `p-state-readonly`, so the readonly styles of `packages/components/src/rating/rating.css` do not apply.
- Visual regression references exist for Windows only; take the linux ones from the screenshot artifact of a CI run.

**Modern look and feel**

Goal: PrimeFaces looks and behaves as current as other UI frameworks (PrimeReact / PrimeVue, shadcn/ui, MUI). Features
other frameworks have and PrimeFaces lacks; each brings its tokens (PrimeUIX 3.0.1 is the reference) and a showcase demo.

- Loading states. Today: autoComplete (search spinner), ajax buttons and links (loading icon), dataScroller (load
  more), outputPanel (deferred), progressBar (indeterminate), skeleton, blockUI (spinner, light mask), ajaxStatus (top
  progress bar). Missing (core):
  - dataTable / treeTable / dataView / dataGrid / dataList: loading overlay (mask + spinner) while paging, sorting,
    filtering or lazy loading, optional skeleton rows instead of the spinner
  - tree / treeTable: per node loading indicator for dynamic (lazy) children
  - selectOneMenu / selectCheckboxMenu / cascadeSelect: loading state of the dropdown icon for lazy options
  - consistent `loading` state for all buttons (commandButton, splitButton, menuButton, linkButton), not only ajax
  - a token themed spinner component (PrimeUIX progressspinner)
- Variants as attributes instead of style classes: see the TODO list in "Variants (style classes)". p:message /
  p:messages / p:growl cannot show secondary / contrast, their severity comes from the FacesMessage.
- Responsive menubar / megamenu (mobile button with a collapsible menu).
- DataTable filter menu (popover with match modes and rules) next to the inline filters.
- DatePicker: year view, highlighted range start / end, clear button / icon.
- Clear icon (`showClear`) for selectOneMenu, selectCheckboxMenu, cascadeSelect, autoComplete, inputText.
- Float label: p:selectCheckboxMenu, autoComplete multiple and chips get no filled class on page load (selectCheckboxMenu
  no focus class while its panel has the focus); the theme detects checked options / tokens / the open panel with

- Sidebar header (title, close) and footer.
- Forced colors (Windows contrast themes): states shown only by a background (selected options / rows, checked

**Material preset** (after the markup changes above)

PrimeUIX Material is more than token values: 32 components carry about 850 lines of preset-specific CSS (filled
inputs with an animated underline, hover / focus halo on checkbox / radio / toggleSwitch, button focus by background,
tab ink bar, card style accordion / fieldset, ...). Those rules target the component markup, so they are ported after
the icon / markup / jQuery UI changes, otherwise twice. Needed mechanism:
- `themes/presets/material.css` (tokens) + `themes/presets/material/<component>.css` (rules), bundled by
  `themes/material.css` into `primefaces-material/theme.css` with its density file. Only loaded when Material is active, so no scoping selector.
- New layer after the components: `@layer primefaces.tokens, primefaces.vendor, primefaces.components,
  primefaces.preset, primefaces.behaviors` (preset rules win without specificity tricks, application CSS still wins).
- `check.mjs` also checks the preset rules (undefined tokens, literal colors / motion); tokens only Material has (e.g.
  halo size) either exist in all presets or use a prefix the parity check exempts.
- Limitation: presets with own rules cannot be mixed on one page via `[data-p-scope]`.

**Animations: JS → CSS**

State changes (hover, focus, colors) and loaders (skeleton, progress, spinners) are CSS already (transitions with the
`--p-*-transition-duration` tokens, keyframes) and respect `prefers-reduced-motion`. These still animate in JS
(jQuery animations set inline styles per frame and `PrimeFaces.effects` uses Web Animations, both override a CSS
transition on the same property):
- Show / hide of overlays (`fadeIn` / `fadeOut`): autoComplete, blockUI, columnToggler, growl, menus, panel / tree
  context parts, pickList, scrollTop, wizard, the overlays in `forms` → CSS enter/leave transitions with
  `@starting-style` + `transition-behavior: allow-discrete` (display / Popover API), the widget only toggles a class.
  Some overlays already work like that: autoComplete, confirmPopup, cascadeSelect, password and selectCheckboxMenu
  toggle the `.p-connected-overlay-enter/exit(-active|-done)` classes, animated in `packages/components/src/base/core.css` with
  `--p-overlay-enter/leave-duration` and `--p-transition-easing-enter/exit`.
- The migrated animations use the motion tokens above (`--p-transition-easing*`, durations).
- Expand / collapse (`slideDown` / `slideUp` / `slideToggle`): accordion, fieldset, inplace, messages, notificationBar,
  panel, panelMenu / menu, tree → height transition with `interpolate-size: allow-keywords` (progressive) or the
  `grid-template-rows: 0fr → 1fr` technique.
- Configurable effects (`showEffect` / `hideEffect` / `effect` with the 15 `PrimeFaces.effects`): dialog, tooltip,
  orderList / pickList, tabView, overlays in `forms` → a few CSS effects (fade, slide, scale) selected by class.
- Scrolling (`animate({scrollTop})`): core, tabView navigator, slideMenu → `scrollTo({behavior: 'smooth'})` /
  `scroll-behavior`, slideMenu with a transform transition.
- Value / special animations: progressBar value (`animate` width → CSS transition on width), clock hands, imageSwitch,
  mindmap, organigram zoom, stack → CSS transitions where the value is a style, otherwise Web Animations API.
- Until then: `$.fx.off = matchMedia('(prefers-reduced-motion: reduce)').matches` (also disables `PrimeFaces.effects`)
  would make the JS animations respect reduced motion with one line in the core.
