# PrimeFaces Theming (prototype)

Design token based themes. Pure CSS, no SASS, everything customizable through CSS variables, light and dark mode built in.
Token naming follows the PrimeUIX convention (`--p-primary-color`, `--p-form-field-background`, `--p-button-primary-background`, ...).

The theme is self-contained: it holds the complete styling of all PrimeFaces components (structure AND look). The CSS that
still lives in the `primefaces` core module (`src/main/frontend/packages/**/*.css`) has been merged into this module and
can be deleted there later (see "Planned (PrimeFaces core)").

## Compatibility: intentionally breaking

The new theming is a clean cut, not a drop-in replacement. There is no compatibility layer and no migration tooling;
applications switch to it deliberately. The legacy themes (`primefaces-themes`, `saga`, `arya`, ...) keep working
unchanged until they are removed.

What breaks for applications that use a token theme:
- **No core CSS:** application CSS that overrides PrimeFaces styles by selector and specificity (e.g. against
  `components.css` of the core or a legacy `theme.css`) may need adjustments; customization is done with tokens.
- **No SASS / theme designer of the legacy themes:** colors, radius, density, icons etc. are CSS variables.
- **Icons:** the icons a component draws itself come from icon tokens (`--p-icon-*`, `--p-<component>-...-icon`), not
  from PrimeIcons / Font Awesome classes. Planned in the core (see below), also breaking for the legacy themes:
  - the JSF attributes for these icons are removed without replacement (e.g. `p:panel closeIcon / collapsedIcon /
    expandedIcon / menuIcon`, `p:rowToggler expandIcon / collapseIcon`, `p:spinner upIcon / downIcon`,
    `p:chip removeIcon`, `p:breadCrumb homeIcon`, ...; full list below). Configure them in CSS. p:tabView has no
    such attributes, its close icon is `--p-tabs-close-icon` already.
  - renderers emit semantic icon classes (`p-icon p-close-icon p-panel-close-icon`) instead of the legacy jQuery UI
    icon classes (`ui-icon-triangle-1-e`, ...), widgets switch states (`aria-expanded`) instead of icon classes.
- **Later, also breaking:** `ui-*` → `p-*` style classes, removal of jQuery UI (the options of `p:draggable` /
  `p:droppable` / `p:resizable` mirror jQuery UI, effect attributes are reduced to a few CSS effects, `p:calendar` is
  removed in favor of `p:datePicker`).

Each breaking core change gets its entry in the migration guide (`docs/migrationguide`) when it is implemented.

## Usage

```xml
<context-param>
    <param-name>primefaces.THEME</param-name>
    <param-value>aura</param-value>   <!-- aura | lara | nora | mylib:mytheme.css -->
</context-param>
```

Everything else is plain CSS in the application:

```css
:root {
    color-scheme: dark;                         /* light | dark | "light dark" (= system, default) */
    --p-primary-base: var(--p-indigo-500);      /* or any color, e.g. #0a7d5a */
    --p-button-border-radius: 2rem;             /* any component token */
}

.sidebar { color-scheme: dark; }                /* dark area inside a light page */

.admin[data-p-scope] { --p-primary-base: var(--p-red-600); }   /* scoped primary color */
```

```html
<html data-p-density="compact">                 <!-- compact | comfortable (spacing of forms, lists, tables, ...) -->
```

- The text color on the primary color (`--p-primary-contrast-color`) follows the primary color: white, or dark text
  for light primary colors (yellow, lime, ...), so any `--p-primary-base` stays readable.
- The primary palette 50-950 is mixed in OKLCH from `--p-primary-base` (even steps, no gray mid tones).
- Density: `density/<preset>.css` scales the spacing tokens of the preset (0.75 / 1.25, generated by
  `tools/generate-density.mjs`). On another element than `<html>` it needs `data-p-scope` too.

The whole theme lives in cascade layers (`primefaces.tokens, primefaces.vendor, primefaces.components,
primefaces.behaviors`), so unlayered application CSS always wins, without `!important` and regardless of specificity.
`base`, `shared` and `components` share one layer: between them specificity and source order decide.

A theme is rendered as two stylesheets: `primefaces-theming:components.css` (icons, third-party CSS and all components,
the same for every theme, stays cached when the theme changes) followed by the tokens of the theme
(`primefaces-theming:aura.css`, or the custom `library:name`). The CSS of the PrimeFaces core library is not rendered
anymore, neither in the head nor in the resource updates of ajax responses (`PrimeResourceHandler#isResourceRendered`).
PrimeFaces does not compress resources: enable gzip/brotli in the server (components.css ~500 KB raw, ~70 KB gzip; a theme ~210 KB raw). PrimeIcons are still loaded (unless
`primefaces.PRIME_ICONS` is false) for the icons applications set themselves (`icon="pi pi-check"`).

## Structure

```
src/main/css/
  presets/aura.css          all tokens of a theme: primitive, semantic and one block per component; the PrimeUIX
  presets/lara.css            tokens and the PrimeFaces tokens (components/parts PrimeUIX does not have) side by side
  presets/nora.css
  density/<preset>.css      compact / comfortable spacing of a preset (generated)
  icons/lucide.css          the icon set: one --p-icon-* token per meaning (close, expanded, sort-asc, ...)
  base/*.css                ui-widget, ui-state-*, core helpers, grid (ui-g), jquery-ui helpers
  shared/*.css              building blocks of several components: inputfield, checkbox, radiobutton, paginator,
                            badge, inputgroup, menu (the common .ui-menu markup incl. menubar)
  components/*.css          one file per tag (keyboard, schedule, tabview, ...); two tags rendering the same widget
                            share the file of the main tag (datepicker + calendar, dialog + confirmDialog, ...)
  behaviors/*.css           dragdrop, resizable, sticky
tools/check.mjs             conventions check, runs before the build (see below)
tools/build.mjs             bundles and minifies the themes (esbuild)
tools/generate-density.mjs  generates density/*.css from the presets (--check: up to date)
tools/export-tokens.mjs     exports the tokens in the W3C Design Tokens format (DTCG) to target/tokens/
```

- The presets are the source of truth and are edited by hand. They started from PrimeUIX 3.0.1 (Aura, Lara, Nora) but
  are not synced with PrimeUIX: PrimeUIX was the template, the presets deviate where that is right (e.g. form fields
  follow the global focus ring in all presets).
- All tokens follow the PrimeUIX naming (`--p-<component>-<section>-<token>`), reference other tokens instead of literal
  colors and live in the block of their component, in all three presets.
- Differences to PrimeUIX: the primary palette 50-950 is derived from `--p-primary-base` via `color-mix(in oklch)`,
  `--p-primary-contrast-color` is computed from the primary color, every semantic/component token is declared on
  `:root, [data-p-scope]`.
- `tools/check.mjs` enforces: every `var(--p-*)` is defined, all presets define the same tokens, no literal colors
  outside presets/ and icons/, no malformed values, the density files are up to date, and every preset token is used (an unused token is
  deleted, not kept for later).

The CSS uses native nesting (states, variants and children nested under their component; selector lists with
different specificity stay flat).

The build (`npm run build` = `npm run check` + `tools/build.mjs` + `tools/export-tokens.mjs`, run by Maven through
`frontend-maven-plugin`) produces `META-INF/resources/primefaces-theming/`:
- `components.css`: icon set + third-party CSS + `base` → `shared` → `components` → `behaviors` (alphabetical inside
  a folder). This order is defined once in `tools/build.mjs`; later rules win on equal specificity, behaviors always.
- `<theme>.css`: `presets/<theme>.css` + `density/<theme>.css`. A custom theme is a CSS file with tokens only.
- `-Dtheming.minify=false` builds readable CSS.
- `target/tokens/<theme>.light|dark.tokens.json`: the tokens in the DTCG format (for Figma / Tokens Studio / Style
  Dictionary), light-dark() resolved per file, `var()` as aliases, color-mix / relative colors / calc resolved, the CSS
  value in `$extensions["org.primefaces.css"]`, density values in `$extensions["org.primefaces.density"]`.

## Icons

The icons the components draw themselves (toggle, close, sort, dropdown, pagination, ...) are SVGs, not an icon font:
the CSS of a component shows a token as mask of a `::before`, the color is `currentColor` and the size the font size.
There are no JSF attributes for them, they are configured with CSS only, on two levels:

```css
/* the icon set: one token per meaning, icons/lucide.css (Lucide, ISC) */
--p-icon-close: url(...);
--p-icon-collapsed: url(...);
--p-icon-expanded: url(...);

/* per component, in the component block of the presets: <component>-<control>[-<state>]-icon */
--p-tree-toggle-collapsed-icon: var(--p-icon-collapsed);
--p-tree-toggle-expanded-icon: var(--p-icon-expanded);
--p-tabs-close-icon: var(--p-icon-close);
```

Overriding (application CSS is unlayered and always wins):

```css
:root { --p-icon-close: url("/myapp/icons/close.svg"); }                    /* everywhere */
:root { --p-tree-toggle-collapsed-icon: url("data:image/svg+xml,..."); }    /* one component */
.sidebar { --p-icon-expanded: url("/myapp/icons/minus.svg"); }             /* one area */
```

- Any SVG works (Font Awesome, PrimeIcons, Tabler, ... all ship SVGs); only its shape is used, it is drawn in the text
  color.
- Use absolute paths or data URIs: a relative `url()` inside a custom property is resolved against the stylesheet that
  uses it (the theme resource), not the one that declares it.
- Directional icons are mirrored in RTL (`scale: -1 1`), so one icon per direction is enough.
- A complete other icon set is a CSS file with all `--p-icon-*` tokens, included after the theme.
- Planned: semantic icon classes in the markup with the same names as the tokens (`.p-panel-close-icon`), for full
  control per icon via CSS (see "Planned (PrimeFaces core)").
- In the source, `url("lucide-static/icons/x.svg")` refers to the npm package and is inlined by `tools/build.mjs`;
  `?fill` fills an outline icon (selected rating star).

## Motion

PrimeFaces tokens (PrimeUIX has durations only), in the semantic block of the presets:

```css
--p-transition-easing: cubic-bezier(0.4, 0, 0.2, 1);       /* something moves within the page */
--p-transition-easing-enter: cubic-bezier(0, 0, 0.2, 1);   /* something appears / slides in (decelerates) */
--p-transition-easing-exit: cubic-bezier(0.4, 0, 1, 1);    /* something disappears / slides out (accelerates) */
--p-overlay-enter-duration: 0.12s;                         /* connected overlays (.ui-connected-overlay-*) */
--p-overlay-leave-duration: 0.1s;
```

Transitions that move something (sidebar, float label, toggle switch handle, speed dial, image compare, overlays) use
them together with the duration tokens; color / border / shadow changes keep the default curve. `tools/check.mjs` fails
on literal curves (`cubic-bezier()`, `ease*`) and literal durations in transitions (`linear`, `steps()` and `0s` are
allowed), so new transitions use the tokens.

## User preferences and accessibility

`base/document.css`:
- `prefers-reduced-motion`: `--p-transition-duration: 0s`, animations and transitions reduced to a minimum.
- Native controls of the application (checkbox, radio, range, progress) use the primary color (`accent-color`), text
  selection the highlight colors.
- Print: light colors, no shadows, scrollable tables print all rows, overlays / growl / paginator hidden.

- Target size (WCAG 2.2, 24px): the small icon controls (chip / token remove, password toggle, breadcrumb home) get an
  invisible 24px hit area; checkboxes, radios and menu items rely on the spacing exception (as in PrimeUIX).

Icons stay visible in the Windows high contrast mode (`forced-color-adjust: none` on the icon, drawn in the forced text
color); focus rings are outlines, which the high contrast mode keeps.

## Responsive components

Paginator (page links), dataTable / treeTable reflow, fileUpload (stacked layout), steps (titles) and full width
selectOneButton / selectManyButton in `.ui-fluid` react to their own width with container queries
(`container: p-paginator / inline-size`, `@container p-paginator (max-width: 640px)`), so they also adapt inside narrow
sidebars or columns. Inline-size containment means the element does not take its width from its content: inside a
shrink-to-fit parent (an auto layout table cell, a flex item without width) give the component a width.
Overlays, sidebars and the legacy `ui-g` grid stay on viewport media queries.

## Third-party CSS

`tools/build.mjs` bundles the CSS of the libraries the components use into `@layer primefaces.vendor` (below the theme):
jQuery UI base, Coloris, jsPlumb, cropperjs, Quill snow, vis-timeline, FullCalendar 5. The npm versions in `package.json`
must be the ones of the core (`primefaces/src/main/frontend/package.json`); the build fails otherwise. jScrollPane CSS is
not needed (PrimeFaces patches the plugin to render `ui-scrollpanel-*` classes, styled by `components/scrollpanel.css`).

## Presets

- The PrimeUIX `timeline` tokens style p:chronoline (`--p-chronoline-*`); `--p-timeline-*` are the tokens of the
  vis-timeline based p:timeline.
- Tokens of PrimeUIX features PrimeFaces does not have were deleted. When such a feature comes (see "Modern look and
  feel" below), its tokens are added in all three presets; PrimeUIX 3.0.1 is the reference for names and values.

## Known limitations

- Inside a `[data-p-scope]` element the theme defaults are re-declared, so token overrides made on `:root`
  (colors and icons) must target `:root, [data-p-scope]` to reach into scopes.
- Canvas based components (chart, knob) take colors from JS options, not from CSS.
- Requires `light-dark()`, `color-mix()`, relative colors (`oklch(from ...)`), `:has()` and container queries
  (Chrome 123, Firefox 128, Safari 18).
- The high contrast mode handling is not verified on Windows yet.

## Planned (PrimeFaces core)

The theming is done without changing the markup of the components. These steps follow in the core:

**Icons** ([primefaces/primefaces#15278](https://github.com/primefaces/primefaces/issues/15278))
- Today the theme picks the icon from the legacy jQuery UI classes the renderers emit (`ui-icon-triangle-1-e` /
  `-1-s`, `ui-icon-closethick`, ...). The widgets will only switch the state (`aria-expanded`, `ui-state-active`)
  instead of swapping icon classes; the CSS selects the icon token by state.
- Renderers emit semantic icon classes instead, named exactly like the icon tokens without `--`: a generic class, the
  meaning and the component specific one.
  ```html
  <span class="p-icon p-close-icon p-panel-close-icon"></span>
  ```
  The theme maps each class to its token once (`.p-panel-close-icon { --p-icon: var(--p-panel-close-icon); }`), so
  there are two ways to customize, with one naming scheme:
  ```css
  /* a different image: tokens (one line, scoped overrides possible, cross the Shadow DOM) */
  :root { --p-icon-close: url("/myapp/icons/close.svg"); }          /* every close icon */
  :root { --p-panel-close-icon: url("/myapp/icons/x.svg"); }        /* panel only */

  /* full control (font icon, size, color of just this icon): the class, application CSS is unlayered and wins */
  .p-panel-close-icon::before {
      mask: none;
      background: none;
      content: "\f00d";
      font-family: "Font Awesome 6 Free";
  }
  ```
  The icon classes are new, so they start as `p-*` right away (no `ui-*` → `p-*` migration for them).
- JSF attributes for icons the component draws itself are removed (breaking, no deprecation phase), they are
  configured with the icon tokens only:
  - remove: `breadCrumb homeIcon`, `chip removeIcon`, `datePicker triggerButtonIcon`, `galleria closeIcon`,
    `menuButton buttonIcon`, `panel closeIcon / collapsedIcon / expandedIcon / menuIcon`,
    `rowToggler expandIcon / collapseIcon`, `spinner upIcon / downIcon`, `dataView gridIcon / listIcon`,
    `triStateCheckbox stateOneIcon / stateTwoIcon / stateThreeIcon`
  - keep (content, chosen per instance): `icon` of buttons and menu items, `expandedIcon / collapsedIcon` of tree and
    organigram nodes (node type icons), `selectBooleanButton onIcon / offIcon`
  - to decide: `speedDial showIcon / hideIcon`, `fileUpload chooseIcon / uploadIcon / cancelIcon`,
    `toggleSwitch onIcon / offIcon`
- Components whose attribute default is a PrimeIcons class (e.g. chip, spinner) render that class, so the theme can not
  replace those icons until their renderers emit neutral markup.

**Other**
- Delete the CSS of the core components (`primefaces/src/main/frontend/**/*.css`, not third-party) once the legacy
  themes are gone; until then `ThemeUtils` / `PrimeResourceHandler#isResourceRendered` suppress it for token themes.
- `RatingRenderer` never renders `ui-state-readonly`, so the readonly styles of `components/rating.css` do not apply.
- `p:message display="tooltip"` adds `ui-state-error` to the tooltip, but there is no invalid tooltip token / style.
- RTL: `shared/inputgroup.css` uses physical left/right for the border collapsing and corners; tree (horizontal),
  toggleSwitch handle, galleria and organigram arrows are not mirrored.
- Later: migration of the `ui-*` classes to `p-*`, and Lit components (the tokens cross the Shadow DOM).
- `primefaces-theming` moves into the `primefaces` module (no separate artifact).
- Overlays: Popover API (top layer, no z-index management) and CSS anchor positioning instead of JS positioning.
- [primefaces/primefaces#15014](https://github.com/primefaces/primefaces/issues/15014)

**Modern look and feel**

Goal: PrimeFaces looks and behaves as current as other UI frameworks (PrimeReact / PrimeVue, shadcn/ui, MUI). Features
other frameworks have and PrimeFaces lacks; each brings its tokens (PrimeUIX 3.0.1 is the reference) and a showcase demo.

- Loading states. Today: autoComplete (search spinner), ajax buttons (loading icon), dataScroller (load more),
  outputPanel (deferred), progressBar (indeterminate), skeleton, blockUI. Missing:
  - dataTable / treeTable / dataView / dataGrid / dataList: loading overlay (mask + spinner) while paging, sorting,
    filtering or lazy loading, optional skeleton rows instead of the spinner
  - tree / treeTable: per node loading indicator for dynamic (lazy) children
  - selectOneMenu / selectCheckboxMenu / cascadeSelect: loading state of the dropdown icon for lazy options
  - consistent `loading` state for all buttons (commandButton, splitButton, menuButton, linkButton), not only ajax
  - a token themed spinner component (PrimeUIX progressspinner) and an optional global ajax progress bar (top of the
    page) for p:ajaxStatus
  - tokens: `--p-<component>-loading-icon-size`, mask background of loading overlays (lighter than the modal mask)
- Size variants (sm / lg) for select, multiSelect, cascadeSelect, checkbox, radioButton, toggleSwitch and badge (sm);
  inputs and buttons have them already.
- Message / staticMessage / growl: variants (simple, outlined), severities secondary and contrast (also tag and badge),
  sizes (sm / lg).
- Responsive menubar / megamenu (mobile button with a collapsible menu).
- DataTable filter menu (popover with match modes and rules) next to the inline filters.
- DatePicker: year view, highlighted range start / end, clear button / icon.
- Clear icon (`showClear`) for selectOneMenu, selectCheckboxMenu, cascadeSelect, autoComplete, inputText.
- Float label variants "in" (label inside the field) and "on" (label on the border), PrimeUIX IftaLabel.
- Sidebar header (title, close) and footer; listbox checkmark mode and striped rows; select checkmark mode.
- Keyboard focus where PrimeFaces has none: growl close button, organigram nodes, autoComplete / chips tokens.
- Empty states: consistent empty message for selects / listbox / multiSelect filters (dataTable, dataView, autoComplete
  have one).
- New components PrimeReact has: InputOtp, MeterGroup, Stepper (modern successor of steps / wizard).

**Animations: JS → CSS**

State changes (hover, focus, colors) and loaders (skeleton, progress, spinners) are CSS already (transitions with the
`--p-*-transition-duration` tokens, keyframes) and respect `prefers-reduced-motion`. These still animate in JS
(jQuery / jQuery UI, setting inline styles per frame, so a CSS transition on the same property would fight them):
- Show / hide of overlays (`fadeIn` / `fadeOut`): autoComplete, blockUI, columnToggler, growl, menus, panel / tree
  context parts, pickList, scrollTop, wizard, the overlays in `forms` → CSS enter/leave transitions with
  `@starting-style` + `transition-behavior: allow-discrete` (display / Popover API), the widget only toggles a class.
  Some overlays already work like that: autoComplete, confirmPopup, cascadeSelect, password and selectCheckboxMenu
  toggle the `.ui-connected-overlay-enter/exit(-active|-done)` classes, animated in `base/core.css` with
  `--p-overlay-enter/leave-duration` and `--p-transition-easing-enter/exit`.
- The migrated animations use the motion tokens above (`--p-transition-easing*`, durations).
- Expand / collapse (`slideDown` / `slideUp` / `slideToggle`): accordion, fieldset, inplace, messages, notificationBar,
  panel, panelMenu / menu, tree → height transition with `interpolate-size: allow-keywords` (progressive) or the
  `grid-template-rows: 0fr → 1fr` technique.
- Configurable effects (`showEffect` / `hideEffect` / `effect` with the 16 jQuery UI effects): dialog, tooltip,
  orderList / pickList, tabView, overlays in `forms` → a few CSS effects (fade, slide, scale) selected by class.
- Scrolling (`animate({scrollTop})`): core, tabView navigator, slideMenu → `scrollTo({behavior: 'smooth'})` /
  `scroll-behavior`, slideMenu with a transform transition.
- Value / special animations: progressBar value (`animate` width → CSS transition on width), clock hands, imageSwitch,
  mindmap, organigram zoom, stack → CSS transitions where the value is a style, otherwise Web Animations API.
- Until then: `$.fx.off = matchMedia('(prefers-reduced-motion: reduce)').matches` (also disables the jQuery UI effects)
  would make the JS animations respect reduced motion with one line in the core.

**Remove jQuery UI** (custom bundle `packages/jquery/jquery-plugins/src/jquery.ui.ts`, datepicker + timepicker addon
of p:calendar)
- `selectable` (unused), `jquery.color`, `$.ui.version` / `uiBackCompat`: remove.
- Helpers: `:focusable` / `:tabbable`, `scrollParent()` → own small utils, `disableSelection()` → `user-select: none`.
- `position()` (autocomplete, calendar, columnToggler, confirmPopup, dialog, overlays, menu, overlayPanel, tooltip) →
  own positioning or Floating UI.
- Effects (dialog, inplace, mindmap, notificationBar, orderList, pickList, tabView, tooltip, wizard) → CSS transitions /
  Web Animations; reduce the effect attributes to a few (fade, slide, scale).
- `datepicker` + timepicker addon: only p:calendar → remove p:calendar, p:datePicker (styled with the
  `--p-datepicker-*` tokens) replaces it; then the calendar rules of `components/datepicker.css` go too.
- `slider`: p:slider (and the p:calendar timepicker) → own implementation.
- `sortable` (dashboard, dataTable, orderList, pickList), `draggable` / `droppable` (p:draggable / p:droppable,
  dashboard, dataTable, dialog, log, tree, treeTable, organigram, diagram, timeline), `resizable` (p:resizable, dialog)
  → own pointer events implementation (or SortableJS / interact.js); the public API of p:draggable / p:droppable /
  p:resizable mirrors the jQuery UI options.
- `jquery-ui-touch-punch` goes with the mouse widgets (pointer events support touch).
- Afterwards: drop the jQuery UI CSS from the vendor layer and `base/jquery-ui.css`.
