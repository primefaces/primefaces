Opting Into the Relative Date Shortcuts

A "date", "time" or "datetime" column offers the ten comparators above out of the box - the ones that work off a date the user picks or types. The relative predicates (Today, This Week, Last N Days, ...) are opt-in: there are eighteen of them for a date and four for a time, so always-on they would make the menu taller than the screen on a column most applications only ever filter with "before" and "after".

Add them with the shortcuts token next to the type: filterValueType="date,shortcuts". Entries are comma separated and appear in the menu in the order given, so individual shortcuts can be named instead of the whole group - filterValueType="date,today,thisWeek,lastNDays" adds exactly those three.

All three columns below filter the very same Join Date field and differ only in their filterValueType. Open each column's match mode picker to compare: ten entries, twenty-eight, and thirteen.

Turning the Match Mode Picker Off Table-Wide

The match mode picker is on by default: every filterable column whose Java type can be resolved gets one, without any configuration. That suits an application that wants to give the end user as much control as possible - but not one that wants a clean, reduced UI with only as many features as needed.

Rather than repeating filterValueType="none" on every column, set it once on the p:dataTable itself. It acts as the default for all of its columns, so the table below filters exactly the way it did before the picker existed: a plain input per column, each fixed to its own filterMatchMode.

A column's own filterValueType is still the more specific statement and always wins, so single columns can opt back in - here Activity, which keeps its "numeric" picker while every other column stays plain.
